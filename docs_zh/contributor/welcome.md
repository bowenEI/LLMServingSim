# 欢迎，未来的贡献者

LLMServingSim 是一个面向**异构与解耦式（disaggregated）LLM 服务基础设施**的研究级模拟器。我们用它在真实硬件上无法提出的场景里问"what if？"：

> *如果我能把这套工作负载跑在一个我没有的 256-GPU 集群上会怎样？跑在 TPU 上？跑在一块未发布的加速器上？横跨 50 个解耦实例？再加上 CXL 或 PIM？*

这是一个来自 **[KAIST CASYS Lab](https://casys.kaist.ac.kr/)** 的 **[Jongse Park 教授](https://jongse-park.github.io/)** 研究组的开源项目，过去两年中在三个学术会议上通过同行评审，并已针对真实 vLLM 完成端到端验证：在全部四个捆绑配置上，TPOT 均值误差在 1.7% 以内，端到端延迟均值误差在 2.2% 以内；RTX 4090 运行的每项指标误差都在 1% 以内。参见 **[验证（Validation）](../validation)**。

**我们正在积极寻找贡献者。** 这不是"欢迎 PR"式的套话，而是真正想一起塑造项目走向的协作者。

如果你在下面看到了任何共鸣之处，我们都想与你合作。

## 项目一览

### 活跃的研究

三篇已发表论文（IISWC 2024、CAL 2025、ISPASS 2026），更多在路上。这个模拟器是实验室做服务系统研究的日常工具，每一份贡献都会落在可衡量的成果上。

### 经过生产验证

对真实 vLLM 在 Llama-3.1-8B、Qwen3-32B dense、Qwen3-30B-A3B MoE 上的端到端误差低于 3%。你预测出来的数字，就是生产环境实际交付的数字。

### 规模小但参与度高

只有几位研究员，但他们阅读每一条 issue 和每一个 PR。几天内就能得到真人回复，而不是机器人分诊。我们真心在意你的贡献能否被合并。

### Apache 2.0，真正的开源

完全开放。无 CLA。你的贡献永远属于你。代码就是我们跑实验所用的同一份代码，没有隐藏分支，没有"内部版本"。

## 你能帮上什么忙

从代码、模型、硬件、文档、示例到想法，每个层面都有贡献空间。以下是当前最需要的：

### 新的硬件后端

添加对 TPU、Intel Gaudi、AMD MI 系列或你喜欢的自定义 NPU 的支持。要么通过基于 vLLM 的剖析器（适用于 vLLM 支持的目标），要么根据厂商模型合成 CSV 包。影响巨大，而范围相对可控。

### 新的模型架构

DeepSeek V3（MLA）、Gemma、GPT-OSS、滑动窗口注意力、未来的 Qwen / Llama 变体。大部分只是一小份 YAML；有些需要轻量的模拟器扩展。这是曝光度很高的工作，研究者会引用模型的覆盖范围。

### 可视化与分析

把每请求 CSV 和吞吐量日志变成有用图表、仪表盘或交互式笔记本的工具。这是一片开放领域，选一个你希望存在的 UX，然后把它做出来。

### 模拟器功能

KV 压缩、投机解码（speculative decoding）、高级批处理策略、网络后端改进（ns3 路径仍在开发中）、更好的 PIM 模型。如果你有研究想法，这里就是它落地的地方。

### 文档与示例

你正在读的这些文档刚刚起步。填补空位、为新场景添加可运行的示例、或为特定研究工作流撰写教程，都极具价值，也是学习代码库的好方法。

### Bug 报告与验证

运行你自己的工作负载，与 vLLM 对比，找出我们发生偏差的情形。提交一个可复现的 bug 就是一份实打实的贡献。`bench/` 套件就是"好"的标准参照。

## 贡献是什么样子

- **你的代码会真正发布。** 每一个合并的 PR 都会直接进入我们跑实验所用的代码库，没有内部分支，没有"以后再清理的版本"。
- **你会得到署名。** 外部贡献者会列在 README 中，紧挨着他们交付的内容（`@waneon`、`@HyunsuYEE`、`@junwha`、`@gleb-kun`……）。你的名字也会出现在那里。
- **有真人审阅你的 PR。** 几天内给出真实反馈。没有机器人分诊，没有"感谢您的关注"式的套话。

## 新来的？欢迎。

你不需要成为服务系统专家才能上手。过去的外部贡献者包括本科生、硕士生、爱好者以及业界工程师，他们都是通过一个入门 issue 或一封"嘿，我能帮忙做 X 吗？"的邮件完成了第一个 PR。

如果你不知道从哪里开始：

1. 阅读[项目 README](https://github.com/casys-kaist/LLMServingSim) 并浏览模拟器文档（你已经在做了）。
2. 挑一件小事：一个错别字、一个空页面、一个缺失的示例配置、一段你看不懂想记录下来的代码。
3. 开一个 issue，写明"我想做 X，这有用吗？"我们会在几天内回复，要么是"好的，请做"，要么引导你去做更有影响力的事。
